# Vibe Iter 使用须知

边试玩、边说意见，结束后把语音和操作一起交给 Agent。使用流程是：**开始测试 → 正常试玩并说话 → 结束测试 → 保存反馈 ZIP → 复制交接提示词**。需要文字时可在保存前等待可选的本机转录完成。

1. **先确认录上了。** 首次使用请完成麦克风授权。打开要测试的游戏页面，点击「开始测试」，等到「录音已验证」、音频大小增长，并确认说话时音量条有变化，再正式试玩。只有计时或 `REC` 标记，还不足以证明麦克风录到了声音。设备页的 5 秒转录测试需要启动可选的本机转录服务。

2. **开始后可以一直玩、一直说。** 无需逐条保存，也无需开启听写；侧栏可以关闭。录音会持续到「结束测试」。请勿在录制中退出 Chrome、刷新或卸载扩展；遇到 `ERR` 应检查状态。意外中断后可恢复已保存内容，但最后约一秒可能丢失。没有保证的最长录制时长，长场次受磁盘和浏览器资源影响，建议按试玩阶段分场并及时导出。

3. **尽量在原游戏标签页内测试。** 同一标签页刷新、跳转会继续记录，其他标签页不会自动加入。页面在后台时无法采样游戏画面；iframe 内部操作目前不采集。

4. **说清对象，稍停再操作。** 例如「这个风铃岛按钮点了没反应」，同时把鼠标放在按钮上。少用连续的「这个、那个」。插件保存点击、键盘、鼠标轨迹和间隔截图；它不是连续录像，快速动画、短暂弹窗可能没有画面，Canvas 内部物体也需要结合截图和项目代码判断。

5. **没文字，不一定没录音。** 录音与转录相互独立。结束后等待转录；失败时先播放原始录音，再启动本机服务 `npm run voice`，点击「转录整场 / 重试」。无需因为「0 条意见」就重新试玩。转录可能认错名称，自动关联也可能有偏差，请保留原音核对。

6. **导出后检查完整性。** 确认 ZIP 实际保存成功，内含可播放的 `audio.webm`、`session.json`、`report.md` 和 `screenshots/`。出现 `AUDIO-MISSING.txt` 表示缺少原音；导出失败请看侧栏错误。只交报告可能漏掉尚未转录的语音。录音和截图保存在本机，导出的文件可能包含私人信息，分享前请检查。

7. **复制到正确的项目 / worktree 对话。** 点击「保存反馈 ZIP」，自动写入 Chrome 下载目录的 `Vibe-Iter` 文件夹；完成后侧栏显示实际地址和交接提示词，点击复制后发给 Codex、Claude 或其他 Agent。每次导出都有唯一文件名；切换标签页和项目名不会改变历史录制的导出信息。提示词要求 Agent 核对当前对话任务、实际 worktree、测试 URL 和端口，不匹配或无法确认时停止修改并提醒你。URL / 端口并不能单独证明属于正确会话；插件没有自动发送或验证会话的能力。本场所有反馈应作为一次完整迭代综合完成并统一验证。可在开始前填写可选的 worktree 路径帮助核对。

首次安装、服务配置与排障步骤见[安装文档](INSTALLATION.md)；也可以把[首页的一句话](../README.md#让-agent-帮你安装)交给 Agent 自动处理。
