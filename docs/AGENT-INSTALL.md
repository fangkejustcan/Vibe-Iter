# Agent 安装与使用协议

这份说明供 ZCode、Codex、WorkBuddy 等能操作本机文件和运行命令的 coding agent 执行。用户只需要把本页地址发给你；下载、校验、解压、环境检查、打开页面和验证均由你完成，不要把本文改写成一长串任务交还用户。

目标：在用户日常使用的 Chrome 中安装 Vibe Iter，并带用户完成首次录制与导出。自动选择合理默认值并继续，只在缺少必要能力、遇到失败或确实需要本人操作时打断用户。

## 默认行为

- 仓库：`https://github.com/fangkejustcan/Vibe-Iter`。
- 优先安装发行 ZIP，基本录制只需 Chrome 116+；不要求用户安装 Git、Node.js、Python 或启动服务器。
- 用户未指定位置时，选择用户可写的固定应用目录：Windows 可用 `%LOCALAPPDATA%/Vibe-Iter/extension`，macOS / Linux 可用 `~/Applications/Vibe-Iter/extension`。不要放在临时目录。
- 使用用户日常的 Chrome。临时自动化浏览器中加载成功，不代表已为用户安装。
- 不要求用户运行命令、选择下载文件、手动解压或理解构建工具；你负责这些步骤。对用户只报告结果和当前必须点击的操作。

## 自动准备安装文件

1. 读取本协议与仓库 `PRIVACY.md`，检查操作系统、Chrome 是否可用和已有安装。已有安装可正常运行时直接验证，不重复安装。升级时保留加载路径和用户数据，录制进行中先结束并导出重要记录。
2. 下载以下文件，确认 HTTP 成功、内容有效：

   - `https://github.com/fangkejustcan/Vibe-Iter/releases/latest/download/vibe-iter-chrome.zip`
   - `https://github.com/fangkejustcan/Vibe-Iter/releases/latest/download/SHA256SUMS.txt`

3. 自动计算 ZIP 的 SHA-256，与校验文件中对应条目比较；不一致则停止。解压前检查没有绝对路径或 `..` 路径穿越。使用系统现有能力下载和解压，不为安装发行 ZIP 增加不必要的依赖。
4. 自动建立固定安装目录并解压。新安装不覆盖无关文件；升级先备份原扩展文件。确认根目录 `manifest.json` 的 `name` 是 `Vibe Iter`、`manifest_version` 是 `3`，并存在清单引用的后台脚本、侧栏和图标。
5. Release 确实不可用时，才回退到下载公开源码。在独立目录检查 Node.js 20+，运行 `npm ci`、`npm run package`，再使用构建产物。缺少构建依赖且不能自行配置时，说明具体阻塞；不要把源码方案作为普通用户的默认路径。

## 完成 Chrome 加载

自动打开用户 Chrome 的 `chrome://extensions` 页面和插件所在文件夹。若已获浏览器操作能力，用它完成可操作步骤；不要修改注册表、企业策略或浏览器安全设置来绕过正常加载流程。

Chrome 不支持直接安装普通 ZIP。需要本人操作时，每次只给当前步骤，例如：

> 已准备好插件，请在打开的 Chrome 页面开启「开发者模式」，点「加载已解压的扩展程序」，选择我已打开的文件夹。

只在无法打开文件夹或用户需要选择路径时展示完整安装路径。加载后检查扩展已启用、名称和版本正确，再打开侧栏与麦克风授权页。麦克风权限由用户确认，不把授权操作报告为已自动完成。

若工具无法操作用户浏览器，仍先完成所有文件准备，再给出最少的加载指引；不要只回复整篇安装教程。

## 验证首次使用

1. 自动打开一个可测试的普通 HTTP/HTTPS 页面，优先使用用户当前项目。不要在浏览器内部页面或真实付款、凭证页面测试。不要启动与录制无关的开发服务器。
2. 打开 Vibe Iter 侧栏，填入对应项目名。引导用户授权麦克风、点击「开始测试」并说一句意见，同时操作页面。
3. 检查「录音已验证」、音频大小增长和说话时音量条变化；计时增长本身不能证明录音成功。工具可检查状态时自行检查。
4. 结束测试并播放原音，请用户确认能听到自己的声音。点击「保存反馈 ZIP」，确认侧栏显示已保存及实际文件地址，自动检查 ZIP 存在可播放的 `audio.webm`、`session.json`、`report.md` 和 `screenshots/`。复制交接提示词即可带入 URL、端口、时间和真实保存路径。没有原音或出现 `AUDIO-MISSING.txt` 时，排查录音后重新验证，不宣称安装验收通过。
5. 验证完成只简短告知：安装成功、如何打开插件、试玩包保存位置。不得把假麦克风或临时浏览器测试当作用户实际麦克风与浏览器已通过验证。

默认不配置转录服务。未启动服务时，结束录制后的转录错误不代表录制失败；播放与导出正常即可使用。不要因此让用户重复录制或选择云端 API。

## 用户需要语音转文字时

自动按 [安装文档](INSTALLATION.md#可选本机语音转文字) 配置可选的本机 Whisper：检查 Python 3.10+，在源码目录创建独立虚拟环境、安装 `scripts/requirements-voice.txt`、预下载 `small` 模型，再启动 `scripts/transcription_server.py`。复用已有的健康服务，不重复启动；监听地址只用 `127.0.0.1:4318`。告诉用户该服务需要在转录时保持运行。

自行检查 `/health` 返回 `ready: true`，然后重试已保存场次的转录，保留原音。浏览器内模型尚未集成，不声称关闭服务后仍可自动转文字。下载失败、依赖缺失等问题先自行诊断，报告确实无法解决的具体阻塞。

## 接收试玩包并修改项目

1. 修改前先核对交接提示词中的 URL / 端口、项目、可选 worktree 路径，与当前对话任务、实际工作目录及开发服务是否对应。同一端口可能复用，同一项目也可能有不同 worktree 和会话。不同或无法确认唯一对应关系时停止修改，不自动切换目录或改动服务；提醒用户可能粘贴错对话，等待确认。确认后自动解压给定地址的 ZIP，读取 `HANDOFF.json` / `HANDOFF.md`（若有）、`README.txt`、`session.json`、`report.md` 与截图。时间以 `session.startedAt` 为基准；原测试标签页、DOM 目标、鼠标坐标和操作用于定位反馈。
2. 没有转录不代表没有意见。先检查 `audio.webm`；能处理音频则结合原音分析，不能时说明能力限制，再按上述流程配置本机转录并重试。
3. 把本场录音、操作、截图和全部反馈视为一次完整迭代，综合分析、完成整体修改并统一运行已有检查。不要拆成互不相关的任务后只完成其中一部分。区分用户原话与推测；不把 Canvas 容器的 DOM selector 当成游戏内部对象，截图是采样画面，不是连续录像。
4. 不上传用户的录音、截图、URL 或试玩包到公共仓库、issue 或无关服务。转录可能识别错误，存在歧义时保留原音并明确不确定之处。

## 排障由你完成

- 下载 404：检查最新 Release；确认不可用后使用源码构建回退。
- 缺少清单：检查是否选择了直接含 `manifest.json` 的目录。
- 侧栏或后台版本不一致：检查加载目录，刷新扩展、测试页与侧栏。
- 无声音：检查 Chrome 授权、系统输入设备、系统麦克风权限与音量条。
- 有录音无文字：保留原音；需要文字时检查本机服务健康状态并重试。
- 无截图：检查原测试标签页是否是所在窗口的活动标签页。

采集边界和数据保留方式以仓库根目录的 `PRIVACY.md`、`docs/USER-NOTES.md` 为准。工具能力不足时如实说明，给用户当前必要的一步操作。
